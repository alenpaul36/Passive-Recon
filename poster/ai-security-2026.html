// Threat briefing · Autumn 2026

AI Security:
when the model acts,
the prompt is the exploit.

AI has moved from chatbots to agents that read, decide and execute: browsing, writing code, calling tools and holding credentials. The attack surface moved with it. Here's what changed and how to defend.

The "lethal trifecta"

Any agent that combines all three can be tricked into leaking data. Remove one leg and the exfiltration path closes.

01How agents get hijacked: anatomy of an indirect prompt injection

The attacker never talks to the model. They plant text where the agent will read it, then let the agent's own permissions do the work.

STEP 1Plant

Hidden instructions go into a web page, email, PDF, ticket, README or tool description.

Label and isolate untrusted inputs; strip hidden text and markup.
STEP 2Ingest

The agent retrieves it while doing a normal task: summarise, triage, fix a bug.

Limit what each task may read. Don't let one agent see everything.
STEP 3Hijack

The model treats the data as instructions, and its goal quietly changes.

Plan before reading; a planner never sees the raw content.
STEP 4Act

It calls tools using its credentials: reads secrets, runs code, edits repos.

Least-privilege, short-lived tokens; sandbox all code execution.
STEP 5Exfiltrate

Data leaves via a link, an image URL, a commit, an API call or a public PR.

Egress allow-lists; human sign-off for outbound and irreversible actions.

02What's new on the threat landscape

Tooling

MCP & tool poisoning

Every MCP server is a new trust boundary. Poisoned tool descriptions and outputs carry hidden instructions. In "agentjacking" (CSA, June 2026), planted error reports led coding agents to run attacker code. MCP still has no signing standard.

Offence

AI-orchestrated intrusions

Attackers use agents for recon, exploitation and lateral movement. In late 2025 Anthropic disclosed a state-backed campaign where an AI agent ran most of the intrusion itself. Expect machine-speed attacks.

Vulnerability research

AI finds the bugs first

Frontier models now find critical flaws in widely used open-source code, which shrinks the time from discovery to exploit. Defenders need the same tools and faster patch cycles.

Supply chain

Poisoned models, skills & packages

Backdoored weights, malicious agent plugins and "slopsquatting": attackers register package names that LLMs hallucinate. Your AI bill of materials is now part of your attack surface.

Identity

Agents as privileged insiders

Agents hold standing API keys, OAuth tokens and service accounts, often in plaintext config. An over-scoped agent hands an attacker a ready-made insider.

Persistence

Memory & context poisoning

Memory and RAG stores let one injection persist across sessions and users. In multi-agent pipelines, one compromised agent can cascade bad instructions downstream.

04Defender's playbook

  • Assume injection succeeds. Limit how much damage a hijacked agent can do.
  • Break the trifecta. No agent gets private data, untrusted input and an outbound channel.
  • Least privilege, per task. Scoped, short-lived credentials, with one identity per agent.
  • Sandbox execution. Isolated containers, no secrets, default-deny egress.
  • Human approval for payments, deletions, deployments and external messages.
  • Vet the AI supply chain. Pin MCP servers, plugins and models; keep an AI-BOM.
  • Log every tool call. Trace prompts, inputs and outputs so you can detect and investigate.
  • Red-team continuously. Adaptive injection tests in CI, mapped to MITRE ATLAS.
  • Turn AI on your own code and find the bugs before attackers do.
