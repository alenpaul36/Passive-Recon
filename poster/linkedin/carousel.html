2026’s AI breaches were old mistakes with an agent in the middle.

Not model failures. Over-trusted input. Over-scoped secrets. Unvetted dependencies. Security teams have handled all three for years. Agents made each one reachable with a sentence.

Treat the model as a parser: everything it reads is input, everything it can touch is blast radius.

One question for every agent

Can it read untrusted text, touch secrets and send data out in the same task? Then someone else can steer it.

Remove one leg per task. It still works on the day a prompt filter misses. Google’s agent guidance says the same in control terms: limit agent powers, keep a named human controller, make actions observable.

OWASP, SAIF and ATLAS describe the attack and the fix. NIST, ISO and the EU AI Act ask you to prove you tested for it. A security programme needs both sets.

Your review bot works for the PR author

April 2026: instructions in a pull request title steered Claude Code Security Review, Gemini CLI Action and GitHub Copilot Agent. Claude’s bot posted its own API key, encoded, in a comment.

Root cause: pull_request_target hands repo secrets to a job that reads text anyone can write.

9.4CVSS, as rated by Anthropic

Any agent triggered by outsiders is a public API with your secrets behind it.

Skills are code, even when they’re markdown

Early 2026: Koi Security found 341 malicious skills on ClawHub, the OpenClaw agent’s marketplace. Bitdefender flagged about 17% of the skills it analysed.

Fake “prerequisite” steps got agents to install the AMOS macOS stealer. One skill padded its README by 22 MB to dodge scanners.

341malicious skills in one marketplace

The lure is a sentence, not a binary, so scanners have little to match. It’s early npm again, with your agent’s permissions.

“Trust this folder?” is the new “Enable macros?”

TrustFall (Adversa AI, May 2026): accepting folder trust starts a project’s MCP servers unsandboxed, with your privileges. Vendors largely treat it as expected behaviour.

CVE-2026-35603: on shared Windows hosts, any user could plant a config in C:\ProgramData that every account’s AI tool loaded.

Neither ISO/IEC 42001 nor the NIST AI RMF names agent least privilege. That control still comes from ISO/IEC 27001 and NIST SP 800-53.
